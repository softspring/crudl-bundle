# Crudl Bundle Features

Functional definition for `softspring/crudl-bundle`.

This package is the Symfony integration layer for `softspring/crudl-controller`. It turns the lower-level controller toolkit into a configuration-driven bundle with service wiring, default forms, default templates, and controller shortcuts for backoffice CRUDL screens.

## Purpose

- Let Symfony applications declare CRUDL controllers in configuration instead of wiring each controller service by hand.
- Provide sensible defaults for list, create, update, delete, and transition screens.
- Reduce repeated setup work when many admin sections share the same CRUDL patterns.

## Main Features

- Register CRUDL controller services from `sfs_crudl` configuration.
- Support controller definitions based on:
  - a custom entity manager service
  - a Doctrine entity class with an autogenerated default manager
- Support action types:
  - `list`
  - `create`
  - `read`
  - `update`
  - `delete`
  - `apply`
  - `transition`
- Generate default event names per controller and action when they are not configured explicitly.
- Provide default Twig templates for common CRUDL screens.
- Provide default entity and filter forms for simple backoffice screens.
- Support dynamic action dispatch through:
  - `controller service + configKey`
  - specific controller methods such as `::list`
  - dynamic action names such as `::list_clients`
- Add Symfony argument resolution so dynamic CRUDL action names receive the current `Request`.

## Expected Usage

- Use the bundle in Symfony applications that already rely on `softspring/crudl-controller`.
- Configure repeated backoffice sections in `sfs_crudl.controllers`.
- Override forms, templates, permissions, redirects, and event names per action.
- Start with bundle defaults for simple admin screens and replace parts gradually when the project needs more control.

## Extension Expectations

- Applications should be able to provide their own manager service per controller.
- Applications should be able to override the default templates and forms.
- Applications should be able to customize the action flow through CRUDL events.
- Applications should be able to combine this bundle with custom query filters, paginators, and workflow transitions.

## Current Limits

- The bundle is focused on server-rendered CRUDL screens, not API controllers.
- Default forms and default list columns are intentionally basic and should be replaced in real projects when the UI or domain becomes more specific.
- The bundle depends on the lower-level behavior and extension points of `softspring/crudl-controller`.
